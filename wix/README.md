# בניית בורר הטעמים של HOUSE OF FLAKES ב-Wix Studio

המסמך הזה מסביר איך להפוך את `prototypes/hof-flavor-picker/v13.html` לרכיב חי באתר Wix Studio.
בתיקייה הזו נמצאים גם הקבצים המוכנים להדבקה:

| קובץ | לאן הוא הולך |
|---|---|
| `public/custom-elements/hof-flavor-picker.js` | לתיקיית `public/custom-elements/` באתר Wix |
| `page-code/flavor-picker-page.js` | לפאנל הקוד של העמוד ב-Studio |

---

## איזה מסלול לבחור

ל-Wix Studio יש שלוש דרכים לממש את הרכיב, והן לא שוות ערך:

| מסלול | זמן | מתאים ל |
|---|---|---|
| **Embed a widget** (iframe) | דקות | סבב אישור מול הלקוח בלבד |
| **Custom Element** ← מומלץ | שעות | הרכיב בייצור |
| **בנייה נייטיבית** (Repeater + Velo) | ימים | לא שווה את זה כאן |

**ההמלצה: Custom Element.** הקוד של הפרוטוטייפ עובר כמעט כמו שהוא, הרכיב מרונדר ישירות
בתוך העמוד (לא בתוך iframe), הוא מקבל את הרוחב האמיתי של הסקשן בכל breakpoint, וקוד העמוד
יכול לדבר איתו לשני הכיוונים.

הערה על בנייה נייטיבית: אפשר לבנות רצועה אופקית עם Repeater ו-CSS scroll-snap, אבל הלולאה
האינסופית והצמדת המרכז נלחמות במחזור האלמנטים של ה-Repeater, והשליטה ב-CSS הפנימי שלו מוגבלת.
בשביל האינטראקציה הספציפית הזו זו עבודה כפולה בתוצאה פחות טובה.

---

## מסלול מהיר: Embed לסבב אישור

לפני שמשקיעים בגרסה האמיתית, אפשר להעלות את הפרוטוטייפ כמו שהוא ולקבל אישור על ההתנהגות:

1. ב-Studio: **Add Elements ← Embed & Social ← Embed a widget**.
2. **Enter Code** והדבקת התוכן של `prototypes/hof-flavor-picker/v13.html`.

מה מקבלים: את הפרוטוטייפ עובד, על דומיין האתר, תוך כמה דקות.
מה **לא** מקבלים, ולכן זה לא מתאים לייצור:

- הכל רץ בתוך iframe בגובה קבוע, עם פס גלילה משלו.
- הרכיב לא יכול לגעת בסל של Wix Stores (רק דרך `postMessage` אל קוד העמוד).
- גוגל לא מאנדקס את התוכן שבפנים.
- 3.4MB של תמונות base64 נטענים בכל כניסה לעמוד.

## המסלול המומלץ: Custom Element, צעד אחר צעד

### 1. העלאת קובץ הרכיב

בעורך או ב-Wix IDE, צרו את הקובץ `public/custom-elements/hof-flavor-picker.js` והדביקו לתוכו את
`wix/public/custom-elements/hof-flavor-picker.js` מהריפו הזה. הנתיב חייב להיות מדויק — Studio
מציע רק קבצים שיושבים ב-`public/custom-elements/`.

### 2. הוספת הרכיב לעמוד

1. **Add Elements ← Embed & Social ← Custom Element**.
2. **Choose Source ← Velo file**, ובחירת `hof-flavor-picker.js` מהרשימה.
3. בשדה **Tag Name** להזין בדיוק: `hof-flavor-picker`
   (חייב להיות זהה למה שמופיע ב-`customElements.define()` בסוף הקובץ).
4. בפאנל המאפיינים לתת לאלמנט את ה-ID‏ `flavorPicker`.

### 3. קוד העמוד

להדביק את `wix/page-code/flavor-picker-page.js` בפאנל הקוד של העמוד. הוא עושה שני דברים:
טוען את הטעמים מה-CMS ומזין אותם לאלמנט, ומתרגם לחיצה על "הוספה לסל" לפעולה בסל של Wix Stores.

### 4. איך הרכיב וקוד העמוד מדברים

Custom Element לא יכול לקרוא ל-API של Velo מתוך עצמו. התקשורת היא דו-כיוונית דרך שני ערוצים:

**פנימה — מאפיינים (attributes):**

```js
picker.setAttribute('flavors', JSON.stringify(flavors)); // מחרוזת בלבד
picker.setAttribute('initial', 'גנאש');
```

**החוצה — אירועים:**

```js
picker.on('flavorchange', (event) => { /* event.detail */ });
picker.on('addtocart',   (event) => { /* event.detail */ });
```

`event.detail` מכיל: `{ name, isSet, size, price, productId, variantId }`
(ב-`addtocart` נוסף גם `quantity`).

## מה חייב להשתנות מהפרוטוטייפ

הפרוטוטייפ בנוי כקובץ יחיד שרץ בלי שרת. כמה מההחלטות האלה חייבות להתהפך באתר אמיתי:

### התמונות — מ-base64 ל-Media Manager

זו הנקודה הקריטית. 15 תמונות מוטמעות כ-base64 = 3.4MB שנטענים לפני שהמשתמש רואה משהו.
להעלות את כולן ל-**Media Manager** (צילומי השקיות + אריחי הרצועה), ולשמור את ה-URL-ים
בקולקציית ה-CMS. Wix מגיש אותן דרך ה-CDN שלו, בפורמט ובגודל שמתאימים למכשיר.

### הנתונים — מקוד ל-CMS

בפרוטוטייפ הטעמים והמחירים כתובים בתוך ה-JS. באתר הם צריכים לשבת ב-CMS כדי שהלקוח יוכל
לערוך אותם בלי מפתח. מבנה קולקציית `Flavors`:

| שדה | סוג | הערה |
|---|---|---|
| `title` | Text | שם הטעם, למשל "גנאש" |
| `order` | Number | סדר ההופעה ברצועה |
| `active` | Boolean | כיבוי טעם בלי למחוק אותו |
| `color` | Text | צבע גיבוי עד שעולה תמונה |
| `tileImage` | Image | האריח ברצועה |
| `bagImage` | Image | צילום השקית בבמה |
| `imageScale` | Number | תיקון גודל, ברירת מחדל 1 (לקוקולד: 1.08) |
| `priceS` / `priceM` / `priceL` | Number | גודל בלי מחיר מוצג מנוטרל |
| `productId` | Text | מזהה המוצר ב-Wix Stores |
| `variantIdS` / `variantIdM` / `variantIdL` | Text | מזהה הווריאנט לכל גודל |
| `isSet` | Boolean | לאריח "מארזים" בלבד |

שימו לב: קבוצות התמחור מהפרוטוטייפ (A: ‎16/32/64‎, B: ‎16/38/76‎) נעלמות כאן לטובת מחיר לכל
טעם. זה מכוון — הלקוח יכול לשנות מחיר לטעם בודד בלי לפרק קבוצה.

### הסל — Wix Stores אמיתי

בפרוטוטייפ "הוספה לסל" רק מקדם מונה. באתר, כל **טעם** הוא מוצר ב-Wix Stores וכל **גודל**
הוא וריאנט שלו. קוד העמוד מוסיף לסל כך:

```js
await currentCartV2.addLineItemsToCurrentCart({
  catalogItems: [{
    catalogReference: {
      appId: '1380b703-ce81-ff05-f115-39571d94dfcd', // Wix Stores, קבוע
      catalogItemId: productId,
      options: { variantId },
    },
    quantity: 1,
  }],
});
await ecom.refreshCart();  // מעדכן את אייקון הסל
await ecom.openSideCart(); // פותח את הסל הצדי
```

### ההדר, הפוטר וטופס יצירת הקשר — אלמנטים נייטיביים

הפרוטוטייפ מצייר הדר, פוטר וטופס בעצמו כי הוא קובץ בודד. באתר כל אלה כבר קיימים כאלמנטים
של Studio, ועדיף כך: אייקון הסל של Wix מתעדכן לבד, וטופס יצירת קשר נייטיבי (Wix Forms) שומר
פניות ב-CRM, שולח מייל ועומד בדרישות נגישות — במקום כפתור שרק מציג "נשלח ✓".
קובץ הרכיב כאן כולל **רק** את הבמה, בורר הגדלים והרצועה.

### מסגרת הטלפון

ה-`.phone` ברוחב 380 והגובה 760 היו פיגום להצגת הפרוטוטייפ. הם לא בקובץ הרכיב. ב-Studio
הסקשן עצמו הוא המסגרת, והרוחב נקבע לפי ה-breakpoint.

### הפונט

לא להטמיע `<link>` ל-Google Fonts בתוך הרכיב. להגדיר את Heebo ב-**Site Styles ← Text Themes**,
והרכיב יורש אותו דרך `font-family: inherit`. תכונות CSS שעוברות בירושה חוצות את גבול ה-Shadow DOM,
ולכן זה עובד גם שהרכיב מבודד.

## SEO ונגישות

**SEO:** התוכן בתוך Custom Element נטען ב-JavaScript. כדי שמנועי חיפוש יראו את שמות הטעמים,
מגדירים `seoMarkup` בקוד העמוד. הסימון חייב לשקף את מה שבאמת מוצג ברכיב — אחרת זה נחשב cloaking.

**נגישות:** הרכיב כאן כבר כולל `role="listbox"` על הרצועה, `role="option"` ו-`aria-selected` על
האריחים, `aria-pressed` על כפתורי הגודל, אזור `aria-live` שמכריז על החלפת טעם, ניווט בחצים
(שמאלה מתקדם, ימינה חוזר — כמקובל ב-RTL), ו-`prefers-reduced-motion` שמכבה את האנימציות.

## מלכודות שכדאי להכיר מראש

1. **Custom Element לא עובד באתר חי בלי Premium.** נדרשים מנוי בתשלום, דומיין מחובר והסרת
   הפרסומות של Wix. בעורך ובתצוגה המקדימה הוא כן יעבוד — מה שמסתיר את הבעיה עד הפרסום.
2. **בעורך ובתצוגה המקדימה הרכיב מרונדר בתוך iframe, ובאתר החי לא.** לכן הוא נראה שונה בין
   הסביבות. אף פעם לא לאשר עיצוב לפי מה שנראה בעורך — רק לפי האתר המפורסם.
3. **`setAttribute` מעביר מחרוזות בלבד.** כל אובייקט חייב לעבור `JSON.stringify` בשליחה
   ו-`JSON.parse` בקליטה. הרכיב עושה את זה ונופל בחזרה לרשימת ברירת מחדל אם ה-JSON פגום.
4. **שם התג חייב להיות זהה בשלושה מקומות:** ב-`customElements.define()`, בשדה Tag Name בעורך,
   ובקוד שמדבר עם האלמנט. חוסר התאמה נכשל בשקט.
5. **הרכיב יכול לשנות את גובה העמוד** כשהוא נטען. כדאי לתת לסקשן גובה מינימלי כדי למנוע קפיצה.

## מה שונה כאן מהפרוטוטייפ, ולמה

מעבר לשינויים שלמעלה, שלושה תיקונים נכנסו לקוד הרכיב עצמו:

- **מרכוז במקום `scrollIntoView`.** בפרוטוטייפ, שממלא את כל המסך, `scrollIntoView` היה בטוח.
  בתוך עמוד אמיתי הוא עלול לגרור את כל העמוד. הרכיב מחשב את ההפרש בין מרכז האריח למרכז
  הרצועה ומשתמש ב-`scrollBy`, שעובד זהה ב-RTL וב-LTR ולא נוגע בגלילת העמוד.
- **`ResizeObserver`.** הפרוטוטייפ מדד רוחב פעם אחת. ב-Studio הרכיב מחליף רוחב בכל מעבר
  breakpoint, והמרכוז מתעדכן איתו.
- **הקבוע `prices` המת הוסר.** בפרוטוטייפ נשארה שורה `{ S: '7.5 ₪', M: '18 ₪', L: '36 ₪' }`
  משארית גרסה קודמת, שאף אחד לא קורא ממנה.
